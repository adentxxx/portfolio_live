VELO – UI Kit

A new UI kit for the redesign of a B2C product for renting mobile, residential, and corporate proxies.

#UI-Kit

Task

The user account was being redrawn from scratch, so the UI kit had to be rebuilt too: for the new visual style and with shared rules, so that development moves faster.

Color palette

Colors are named as tokens. Each has a name and a short note on what it’s for. That makes it easier to pick a color or add a new one, for the designer and the developer alike.

Colors are split into groups: text, icons, background, borders. Each one is checked for contrast, especially text and interactive elements. The accent text color is darker than the accent background. Dark text on light and light text on dark can’t share the same saturation.

Typography

The type was rebuilt. The main typeface is HarmonyOS Sans. It’s a grotesque: easy to read on screen, and it covers the languages we need.

Text styles

Instead of a long list of sizes and line heights, three groups remain: headings (Header), body text (Body), and footnotes (Footnotes). Every style has its place, so it’s easier not to invent new sizes in a layout.

Iconography

We needed an icon library for the product’s common and rare scenarios, in one visual style and with room for new icons.

Selection principles

Every icon solves a specific task; I added nothing extra. They are tuned to the palette and the typeface. Statuses and notifications are recognizable thanks to contrast. All icons are built as components in several sizes.

What’s in the library

• Core icons: navigation, statuses, actions, tables. • File icons: upload and common formats. • Country flags: for choosing a location in a dropdown, a list, and a card, with padding and several sizes.

Components

Next I built a component library in Figma following the atomic approach. The components scale easily, cover many scenarios, and are ready to be handed over to the front end.

Principles

I removed duplicate sizes and visual noise. Every component belongs to one system and is configured through Figma Properties, with no copies. The structure is designed to be carried over into code.

Buttons

Buttons cover the main scenarios. • Sizes: 48, 40, 36, 32, and 20 px, for different screen densities. • States: Default, Hover, Pressed, Disabled. • Types: Primary, Secondary, Tertiary, Outline, Outline Black. • There’s an Only Icon mode and icons on the left and right.

Inputs

Input fields for the product’s tasks. • Sizes: 44 and 40 px. • States: Default, Active, Error, Disabled.

Extra options

• Mode: Outline and Filled. • Corners: an 8 px radius can be turned on. • Active Placeholder: the placeholder moves up and becomes a label. • Tags: entering values such as GET and POST. • Icon Left / Right / Right 2: supporting icons. • Link: a link inside the field, for example “Forgot password?”.

Checkboxes

Two checkbox components. • Master Checkbox is used in tables and lists. • Checkbox with text suits forms where the choice comes with a label.
